# Unified Pen Plans and Force Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task. Native execution is the user's preserved choice. Track steps with checkboxes.

**Goal:** Implement HAR-48 using one schema-3 physical plan, validated force commands, and explicit operator setup acknowledgement.

**Architecture:** Pure immutable plan/force records sit behind one resolver and serializer. Shared HP-GL tokenization supports force-state and placement validation. Conversion emits reviewed pass artifacts; preflight and sender enforce their hashes, physical selections, force expectations, and setup confirmation.

**Tech Stack:** Existing Python 3.11-3.13, standard library, vpype, pySerial, pytest and Ruff; no new dependencies.

**Spec:** [Approved design](../specs/2026-10-11-dpx3300-pen-force-design.md).

## Global constraints

- Worktree `.worktrees/plotter-pen-force` under viz_virtualserver is a plotter-workflow worktree on `feat/har48-pen-force`; never edit either root checkout.
- Sole authored/resolved schema version is strict integer 3. No v1/v2 fallback, nested wrapper, or parallel final resolver.
- Forces: 20, 35, 50, 65, 80, 95, 110, 125 gf; generated codes 1, 3, 5, 7, 9, 11, 13, 15. Equivalent even codes validate to the same force.
- Force is optional. When present, every used physical slot must have an explicit effective value; never infer device defaults or apply 65 gf to unrelated jobs.
- Software mode requires AUTO off; panel mode requires AUTO on plus panel settings, acknowledged by `--confirm-pen-plan` even for a single pen.
- No hardware I/O during development or tests, no AUTO switching, no new dependencies, and no viz_virtualserver schema changes.
- Maintain geometry/placement, atomic publication, distinct authored/resolved suffixes, and current CLI defaults for absent authored plans.
- Rejection of an invalid discovered sidecar cannot be bypassed by legacy flags.
- Preserve native execution, one fresh final reviewer, commit identity r-ballard / russellcballard@gmail.com, and push/create PR without merging automatically.

## Review focus

1. Command-like strings inside labels and changed DT terminators cannot alter parsed force/reset state (Task 2).
2. SP0, missing selection, or unsupported drawing instructions cannot evade force-at-drawing validation (Task 2).
3. An override-only plan must fail if a later pass uses an unspecified slot (Task 3).
4. A hash-correct sidecar with edited effective forces or pen ordering must still fail (Task 4).
5. Legacy bypass flags and single-pen jobs must not skip force acknowledgement (Task 5).

## File map and interfaces

Create:

- `pen_force.py`: immutable `ForceSpec(mode, default_gf, slot_overrides)`; slot overrides are tuples of `(slot, gf)`. `parse_force(raw: object) -> ForceSpec | None`, `effective_force(spec: ForceSpec, slot: int) -> int | None`, `force_code(gf: int) -> int`, `force_gf(code: int) -> int`, `force_payload(spec: ForceSpec | None) -> dict | None`.
- `hpgl_commands.py`: `HPGLCommand(opcode: str, arguments: str, start: int, end: int)`, `tokenize_hpgl(text: str) -> tuple[HPGLCommand, ...]`; offsets refer to original text. Parsing failures raise `HPGLParseError(ValueError)`.
- `hpgl_force.py`: `apply_force(text: str, spec: ForceSpec | None) -> str`, `validate_force(text: str, spec: ForceSpec | None, used_slots: tuple[int, ...]) -> None`; failures raise `ForceValidationError(ValueError)` with command/slot context.
- `pen_plan_models.py`: frozen `LayerInfo(id: str, active: bool, ordinal: int)`, `SlotSpec(slot: int, tool: str | None, color: str | None, label: str | None, notes: str | None)`, `Assignment(layer_ids: tuple[str, ...], physical_slot: int)`, `PassSpec(id: str, assignments: tuple[Assignment, ...])`, and `PenPlanSpec(policy: str, passes: tuple[PassSpec, ...], slots: tuple[SlotSpec, ...], omitted_layers: tuple[str, ...], repeated_layers: tuple[str, ...], pen_force: ForceSpec | None, notes: str | None)`. Defaults for optional slot texts are None; optional plan sequences default empty. Define `ForceAudit(spec: ForceSpec, effective_slot_forces: tuple[tuple[int, int], ...])` and `ResolvedPlotPass` below. Schema/kind constants belong here.
- `pen_plan_io.py`: strict authored parsing and resolved serialization/validation. `parse_pen_plan(raw: object) -> PenPlanSpec`, `load_pen_plan(path: Path) -> PenPlanSpec`, `resolved_payload(plan: ResolvedPlotPass) -> dict`, `load_resolved_plot_pass(path: Path) -> ResolvedPlotPass`, `write_resolved_plot_pass(path: Path, plan: ResolvedPlotPass) -> None`.
- `tests/test_pen_force.py`, `tests/test_hpgl_commands.py`, `tests/test_hpgl_force.py`, `tests/test_pen_plan_v3.py`, `tests/test_pen_force_conversion.py`, `tests/test_pen_force_preflight.py`.

Modify:

- `pen_plan.py`: single source-normalization/resolution facade, discovery, pen remapping and formatting; retire old model/parser/sidecar branches after cutover. Public APIs: `inspect_plan_layers(source_svg: Path) -> tuple[LayerInfo, ...]`, `resolve_plot_passes(layers: tuple[LayerInfo, ...], spec: PenPlanSpec) -> tuple[PassSpec, ...]`, `validate_resolved_sidecar_for_hpgl(hpgl_path: Path, sidecar_path: Path | None = None) -> ResolvedPlotPass`, `format_resolved_plot_pass(plan: ResolvedPlotPass) -> str`.
- `hpgl_placement.py`, `scripts/preview_hpgl.py`: consume shared tokens; retain public coordinate/preview result contracts. Physical-pen extraction/remapping also consumes tokens.
- `scripts/dpx3300_convert.py`: both source import paths consume the same pass model and serializer; integrate force before validation/hashing/publication.
- `scripts/job_preflight.py`, `scripts/send_hpgl.py`: shared resolved model and force confirmation/status gates.
- `penplan.schema.json`, current affected tests/fixtures, all `examples/penplans/*.penplan.json`, `docs/reference/pen-plan.md`, `docs/reference/job-preflight.md`, `docs/how-to/plotter-playbook.md`, `README.md`.

ResolvedPlotPass fields are `source_svg: str`, `source_svg_sha256: str`, `source_manifest_hash: str | None`, `pass_id: str`, `pass_number: int`, `pass_count: int`, `policy: str`, `assignments: tuple[Assignment, ...]`, `physical_slots: tuple[int, ...]`, `omitted_layers: tuple[str, ...]`, `repeated_layers: tuple[str, ...]`, `slots: tuple[SlotSpec, ...]`, `hpgl_sha256: str`, and `pen_force: ForceAudit | None`. Serializer supplies version3 and kind constants. ForceAudit serializes as `{spec: <force_payload>, effective_slot_forces: [{slot, force_gf}, ...]}`. No duplicate resolved legacy/logical types remain at completion. Retain discovery/path helpers with their current signatures; change `plan_has_documented_tools(plan: ResolvedPlotPass) -> bool` to consume applicable slot records.
